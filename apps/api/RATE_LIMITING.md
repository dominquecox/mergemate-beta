# Shared API admission

Every network request that reaches the API uses the same authoritative SQLite Durable Object for its environment, identity and scope. Public/failed-auth requests and OPTIONS share the IP scope (60 admissions per60seconds). Valid private sessions use the session scope (300 per60seconds). Support additionally uses its own IP scope (5 per60seconds). Signed webhook routes retain their provider-IP exception and perform their signature/body checks separately. These are per-identity allowances, not a single global allowance for all users.

The namespace name is a deterministic SHA-256 digest of environment/scope/identity with a scope prefix. Raw IP addresses and session credentials are never passed to the object or written to its SQL tables. Hashes are pseudonyms, not anonymization. The object stores only admission timestamps, its fixed scope, and a monotonic logical-clock watermark. Synchronous SQL transactions prune the half-open window `(now-60s, now]`, count its admissions, and insert only when capacity remains. No await separates count from insert. Denied requests add no event rows; each object holds at most its scope allowance plus one clock record. An alarm prunes expired events; idle objects retain an empty schema and clock watermark.

The API returns429/rate_limited with the rounded-up remaining wait for the oldest admission. Missing, failed, timed-out or malformed authoritative replies return503/rate_limit_unavailable and never run the handler. An RPC that finishes after the API deadline may consume a slot for a request already answered503; this is conservative and cannot increase admitted work. The client is given a generic temporary-unavailability message, never a raw exception or identity.

## Cache and deployment boundary

Workers Cache is explicitly disabled in local/dev/production Wrangler configuration. API HTTP responses are also no-store; the internal KV snapshot cache remains available after admission. There is no response Cache API fast path. Cache-Control alone is not the evidence: check the resolved Worker configuration for `cache.enabled=false`, the namespace/class migration, and the exact released version. Cloudflare documents the pre-Worker cache at https://developers.cloudflare.com/workers/cache/ and its configuration at https://developers.cloudflare.com/workers/cache/configuration/ .

The additive `v2-rate-admission` Worker migration creates a SQLite class; it does not reset the existing token-refresher class or require a product D1 migration. Binding namespaces differ by Worker environment and the key also includes the environment. Deploy all traffic to the reviewed admission-enabled version; do not mix old uncoordinated versions with it. Let requests admitted by the old version drain beyond one full window before claiming a cross-cut rolling-window receipt. Do not delete/reset the namespace or change the key/environment identity during a window. Rolling back to an older limiter reintroduces its old limitation; choose an admission-enabled rollback version or an explicitly controlled maintenance response.

No paid WAF is required by this implementation. Durable Objects still consume request/storage/duration usage under the account plan; this is not unlimited free traffic or a general volumetric DDoS defense. Live latency, bindings, cache settings and staged concurrency remain deployment acceptance evidence. No live burst is executed by these local tests.

## Local proof

`npm run check` includes real workerd/SQLite tests using the locked Miniflare runtime: concurrent60/300/5 ceilings, rolling boundaries and Retry-After, process restart with persisted storage, alarm cleanup, identity isolation, and actual API OPTIONS/warm public GET admission with CORS. Middleware tests verify503 failure/deadline behavior, deterministic environment hashing and cache configuration. Existing auth/CSRF/suspension/webhook tests remain in place. The test-only clock/router/subclass is not exported by production.

The runtime fixture uses Miniflare5's `resourcePersistencePath`; legacy per-resource persistence options are not accepted as proof. Test controls and fake compatibility-limiters exist only in test files. Production no longer has approximate per-location limiter bindings. Wrangler type generation and dev/production dry runs validate the actual class/binding/cache source before an owner-authorized release. Local runtime proof does not establish deployment or cross-region live behavior.
