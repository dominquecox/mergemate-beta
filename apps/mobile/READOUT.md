# Device-local readout (J-001)

`voice_readout` defaults off. A signed-in startup, foreground return and60-second active refresh read the public, credential-free flags with strict booleans and fail closed. Reads are bounded/deduplicated; rapid foreground events defer at most5seconds rather than abandoning refresh. Refresh stops current narration before checking the configuration. Missing, malformed, unknown or unavailable flags hide all readout controls. No source change enables a live flag. PR111 owns the shared3flag/Highlight rollout: preserve its `highlight:false` default in the shared flag cache when reconciling this branch after111.

Inbox reads only aggregate counts for the currently loaded list. PR detail reads existing summary fields and risk text, never patches, PR body, comments or secret-finding records. Conservative filtering drops code blocks/inline code, links, filenames/paths, credential-shaped values, emails and secret-bearing sentences before removing formatting. Text is bounded to80sentences of at most600characters; it stays in memory. Readout requests no new summary, risk, provider or recording permission. Native/browser voices process the filtered text through device speech APIs only.

Play/Pause/Resume/Stop and0.75/1/1.25/1.5speed are user-triggered. Concurrent Play taps do not queue another read. Each utterance has a generation/token guard, so cancelled, duplicate and obsolete callbacks cannot advance narration. Android repeats the current sentence on Resume because its TTS API has no pause. Changing speed while paused restarts that sentence at the selected speed on Resume. Blur, background/pagehide, text changes, sign-out, account deletion, session expiry and flag-off stop speech; foreground return never resumes automatically.

## Platform boundary

- Browser: selects an explicitly local `SpeechSynthesisVoice.localService` voice. A remote-only or missing voice list is unavailable; there is no remote fallback. A user may install an OS voice and retry Play.
- iOS: uses the SDK-compatible `expo-speech58.0.3` installed voice identifier and OS pause/resume. Silent mode and actual installed voices require a device check.
- Android: `modules/offline-voice` prefers installed offline voices and rechecks the chosen voice before synthesis. The speech driver falls back to the system `expo-speech` engine if the offline adapter is absent, enumeration fails or no offline voices exist. That system engine may use network services under device settings; this is disclosed in the UI. Pause stops and Resume repeats the current sentence. Real audio, offline preference and lifecycle require physical-device acceptance; JavaScript packaging alone cannot prove them.
