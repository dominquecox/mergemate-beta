# Optional feature switches

The public `/v1/flags` document supplies `voice_readout`, `voice_notes` and `highlight`. The shared contract accepts literal booleans, defaults missing switches off, and rejects unknown/malformed input. The app caches a validated document in memory for at most 60 seconds, deduplicates concurrent reads, and never serves an expired enabled value while revalidating. Failed reads become all-off; logout/session changes invalidate pending reads. Flag requests omit credentials. No source change enables a live flag.

Inbox hides the Highlight entry until enabled. Direct navigation to `/highlight` displays an unavailable state while off or loading and exposes no picker, camera or analysis action. The API independently checks the same flag before consent/analysis work; stale clients cannot bypass the server. The shared reader also exposes the two voice switches for their feature implementations; this PR does not claim to complete those voice tickets.

Fixture smoke: export with `EXPO_NO_TELEMETRY=1 EXPO_PUBLIC_API_BASE_URL=https://api-dev.mergemate.dev npm run export:web -w @mergemate/mobile`, then run `node apps/mobile/scripts/check-feature-flags.mjs`. The script starts a loopback server on an ephemeral port, intercepts all external API transports, visits Inbox and Highlight with on/off/malformed/unavailable documents at393/1440, checks the entry/picker availability and zero analysis requests, and saves screenshots under `/private/tmp/mergemate-feature-flags`. It uses installed Chrome; it performs no real sign-in, camera capture, model request or deployment. Unit tests exercise strict parsing, expiry, concurrent reads, failure closure, session invalidation and credential omission. Native JS exports verify packaging only; signed-device camera/accessibility acceptance remains separate.
